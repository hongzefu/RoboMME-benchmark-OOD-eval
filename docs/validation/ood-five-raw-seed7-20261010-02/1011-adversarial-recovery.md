## 已定位的故障

原 `qwenvl-02-full` 在单局一千八百秒墙钟期限后自行退出。Slurm 原步骤 `63664393.7` 的实际状态为 `FAILED`、退出码 `75:0`。旧生产器的硬退出绕过正常收尾，原进度仍为 `episode`，报告仅有稀疏基础设施失败字段。控制器先按普通成绩要求字段，随后退出；这不能归为 SSH 断开或 GPU allocation 消失。

## 验证边界与状态矩阵

| 状态或故障 | 必须保持的行为 | 必须取得的证据 |
|---|---|---|
| 普通成功、普通失败 | 独立成功字段按实际观察为零或一；交付原始媒体并继续下一身份 | 真实结果序列化、席位结算、控制器发布、搬运和消费者 |
| 模型异常、执行步数期限 | 保留已观察成功位；正常失败不重试；执行步数不越界 | 真实 `run_episode` 与终态报告读回 |
| 成功观察未知、协议或记录失败 | 保留未知与首因，不能混入正常成绩 | 基础设施分类及未知值拒绝夹具 |
| 墙钟、首推理、媒体收尾期限 | 有限硬退出七十五；原身份只结算一次；不得领取下一局 | 真 CPU 子进程及跨线程竞争反例 |
| 报告、领取、预算写入边界中断 | 幂等恢复原身份，不能重复首试、发布或扣预算 | 每个写边界前后故障与重新读回 |
| 零、六、七十五退出；报告或记账晚到 | 在有界窗口内确认原步骤，健康席位继续；失败身份不重新领取 | 报告可见性、实际退出、步骤记录与续段号夹具 |
| 人工停止且已有基础设施失败 | 正常加失败等于已结算；剩余按未尝试计算；证明和指针一致 | 真控制器暂停证明写入、读回和恢复 |
| 完整或不完整终态 | 按原四千身份互斥覆盖；有基础设施失败只写不完整，不伪报全量交付通过 | 控制器到真实搬运报告，再到直接、附着和 shell 消费者 |
| 历史错误与新错误 | 历史原字节保留，严格路径和 SHA 认可；新错误仍被拒绝 | 同路径改字节、新实例错误及原 SHA 不变 |
| 监督器或查询异常 | 只停止监督器自身；GPU 不主动取消，CPU 保持占位 | 有限查询、通知与占位外壳的 CPU 夹具 |

以上矩阵区分真实生产者链路与人工状态夹具。CPU 验证不加载模型、不申请 GPU、不产生额外真实 reset 或轨迹；真实模型输出和全量四千身份最终交付仍由正式评估结果证明。邮件发送退出零只表示提交成功，不能当作目标收件箱实收。
