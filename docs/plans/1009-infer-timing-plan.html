附·三、客户端与服务端都能测：怎么测、改在哪

客户端（权威）：五处各一个 time.perf_counter() 对，包住「ws.send 观测 → ws.recv 回复」。SimpleMemVLA、FrameSamp、GroundSG 已有该对，只是字段名不一；PonderPounce、Astra 新加。统一写进 timing.policy.chunks[]，每项 {decision, env_step, client_rtt_ms, server_infer_ms, pack_ms, unpack_ms}。

服务端（辅助）：

  • mme-vla（FrameSamp／GroundSG／Astra-VLA 共用）：AuditedPolicy.infer 在 self._inner.infer(obs) 前后 perf_counter，结果写 out[AUDIT_KEY]["server_timing"] = {"infer_ms": …, "gpu": torch/jax 设备名}。第三方 infer 末尾已 np.asarray 落地，所以这个区间是真实的「预处理 + 前向 + 回传主机」。
  • PonderPounce：SubgoalReportingServer._fire_s1 包住 super()._fire_s1（predict_action 返回 CPU tensor，已同步），把 s1_infer_ms 挂到 ep.chunk；_dispense 判断 ep.chunk.cursor == 1 即「这一步是新 chunk 的第一行」→ 审计块 pp_timing = {"chunk_fresh": True, "s1_infer_ms": …, "n_s1_fires": …}。客户端收到后把该步 RTT 记为该 chunk 的 client_rtt_ms。
  • SimpleMemVLA：已有 infer_ms，只改字段名映射。

客户端 RTT 与服务端前向的差 = 编解码 + 回环网络，FrameSamp 现有 network_mean_s 就是这个量；验收时要求五个模型的 client_rtt_ms − server_infer_ms 中位数为正且在同一量级（见 §五）。

附·三′、双系统的子目标生成也要测清；单模型内「语言推理 vs 动作」能否拆开

用户追问（2026-10-09）：「这个是双系统的 subgoal 生成的也要清楚 然后如果不是双系统或者说内部 Language Reasoning 和 Action 是不是都可以测分开测出来」。结论：五个模型都能把「语言／子目标」与「动作」拆成两列，且全部在本仓代码内做到，零第三方源码改动。拆法分三类：

模型 结构 语言／子目标怎么测 动作怎么测 两者关系
PonderPounce 双系统：Ponder（S2，_fire_s2）出 cognition+subgoal，Pounce（S1，_fire_s1）出 chunk 本仓 pp_server_wrap.py::_S2Watch.fire 已包住第三方 ctx.fire（同步调用），在里面加 perf_counter 得 s2_infer_ms，随现有 pp_generation 块回传 _fire_s1 外包计时得 s1_infer_ms（§三） 独立两次前向，各自触发（仿真钟 1000 ms），可分别统计
GroundSG 双系统：子目标预测器（Qwen／MemER）在评估进程内，动作在 mme-vla 服务端 本仓 groundsg.py::make_policy_context 在 build_predictor 返回后包一层代理，get_subgoal 前后 perf_counter（含 torch.cuda.synchronize，模型在本进程）得 subgoal_ms 列表 chunk_rtt_ms / server_infer_ms（§三） 独立，默认都开（原 §二「可选默认关」作废）
Astra 双系统：规划器（远程 API）+ 监视器（本地）+ VLA 第三方 runner.py 已逐次记 planner / monitor / second_button_review 的 seconds 进 decisions.jsonl；本仓只汇总，不改 TracedClient.infer 外包（§三） 独立；规划器 seconds 含 20 s 发送间隔与退避，报表单列并注明
SimpleMemVLA 单模型：同一次 generate_batch 先自回归生成 subtask token，再 self.model.action_head.sample(...) 出动作 本仓 smvla_server.py 在 SMVLAPolicyHost.__init__ 把 self.batched.model.action_head.sample 换成计时代理：进入时 torch.cuda.synchronize() 打点 t_lang_end，调原 sample 后再 synchronize 打点 t_act_end；lang_ms = t_lang_end − t0（t0 为现有 infer 起点，含预处理），action_ms = t_act_end − t_lang_end 同左 action_ms 串行同一前向，两段相加 ≈ 现有 infer_ms（验收：差 < 1%）
FrameSamp 单模型，无语言输出 无（报表填 —） chunk_rtt_ms / server_infer_ms —

SimpleMemVLA 这一处是对第三方模型对象方法的运行时替换（第 21 条意义上的「覆盖」，但 third_party/SimpleMemVLA 不在 <PROTECTED_DIRS>），不改第三方源文件、不改随机数、不改输出；SGEVAL_AUDIT=0 时不安装代理。替代方案是在 fork 分支改 batched_policy.py 加时间戳，改动更重、要升 gitlink，不推荐。

统一字段：timing.policy.lang_calls[]（每次语言／子目标调用 {index, env_step, ms, kind: s2|subgoal|planner|monitor|lang_in_forward}）、lang_summary（同 chunk_summary 三段统计）。报表速度表加两列「语言稳态 mean」「动作稳态 mean」。

  • result.json：timing.policy.chunks[]（逐 decision）+ timing.policy.chunk_summary（n / first_ms / second_ms / third_ms / steady_mean_ms / steady_p50_ms / steady_p95_ms，client 与 server 各一套）+ timing.policy.gpu_name。
