PonderPounce：客户端每步往返只记 step_rtt_ms[]；decision_wall_ms = 审计块 chunk_fresh=True 那一步的往返 + 自上一 fresh 步以来非 fresh 步（含首个 chunk 前的 hold 步）触发的 Σ s2_infer_ms（Ponder 的工作归属到它服务的下一个 chunk，不漏记）；action_rtt_ms = fresh 步往返 − 当步 s2_infer_ms；lang_ms = Σ s2_infer_ms。服务端审计块 chunk_fresh 由 ep.chunk.cursor == 1 判定（_fire_s1 新建 Chunk(cursor=0)，同请求内 _dispense 加到 1）；hold 步 ep.chunk is None 判 False；客户端最终 fresh 判据为 chunk_fresh 且 n_s1_fires 递增，不符记 fresh_mismatch、不崩；H=1 且 S1 周期等于步长时每步 fresh（测试断言），其余 H=1 情形靠 n_s1_fires 递增判定。

模块常量 - LANG_KINDS = frozenset({"subgoal", "s2", "planner", "monitor", "review", "lang_in_forward"})：累加进 lang_ms。 - DETAIL_KINDS = frozenset({"ask"})：只进 lang_calls[] 明细，不累加。其他 kind → ValueError（拼错立刻炸，不静默漏算）。白名单不扩：Astra 直接用 planner / review（即 review_second_button）/ monitor 三个 kind。 - MODEL_KINDS = ("serial", "pp", "smvla")；SERIAL_TOL = 0.20；PP_TOL_MS = 1.0。 - CHUNK_FIELDS = ("decision_wall_ms", "action_rtt_ms", "server_infer_ms", "lang_ms")（smvla 另统计 observe_rtt_ms 与 slack_ms = decision_wall_ms − observe_rtt_ms − action_rtt_ms，只报数不判）。字面量 chunk_rtt_ms 全模块不出现（测试 grep 钉死）。

class ChunkTimer（单线程使用；不加锁，文档写明） - 状态：chunks: list[dict]、lang_calls: list[dict]、_t_obs: float | None、_bucket_ms: float、_bucket_n: int、_clock = time.perf_counter（构造参数 clock= 可注入，测试用假时钟）。 - start(t=None)：_t_obs = clock() if t is None else float(t)。重复 start 覆盖（取最后一次；PP 的非 fresh 步、Astra 首个代理调用后再触发都不应拉长）；不清桶——start 之前已 add_lang 的条目仍归入下一次 close（Astra 监视器先于 t_obs？不会，代理首次调用即 start；PP 的 S2 在 fresh 步之前发生，正是要并入）。 - add_lang(ms, *, kind, env_step, **extra)：校验 ms 为有限非负数（否则 ValueError）；追加 {"index": len(lang_calls), "env_step": int, "ms": round(ms,3), "kind": kind, **extra}（retry/reuse/s2_fired 等走 extra，None 值剔除）；kind in LANG_KINDS 时 _bucket_ms += ms; _bucket_n += 1。允许在任何时刻调用（start 前、close 之间）。 - close(*, decision, env_step, action_rtt_ms: float | None, server_infer_ms: float | None, extra=None, t: float | None = None) -> dict：t 为显式终点时刻（perf_counter 刻度，不传取 clock()），与 start(t=) 对称；action_rtt_ms 与 server_infer_ms 均允许 None（客户端替身缺属性时记 None，由各客户端自行计数 timing_missing，助手不计）； - 未 start 就 close → RuntimeError("ChunkTimer.close without start")（客户端漏打 t_obs 是 bug，不兜底成 0）。 - decision_wall_ms = ((clock() if t is None else t) - _t_obs) * 1000；lang_ms = _bucket_ms（close 前没有 add_lang 时为 0.0，显式写零，不省略键——P4 序列化教训）。 - 记录 {"decision", "env_step", "decision_wall_ms", "action_rtt_ms"(可 None), "server_infer_ms"(可 None), "lang_ms", "n_lang": _bucket_n, **extra}；extra 与保留键冲突 → ValueError；保留键清单 RESERVED_KEYS = {decision_wall_ms, action_rtt_ms, server_infer_ms, lang_ms, decision, env_step, n_lang, phase}。phase 在 close 时按本条在 chunks 中的原始序号标定：0→first、1→second、2→third、≥3→steady；之后任何缺失过滤或分层都只读 phase，不重新按位置切。has_planner、reuse、smvla 的 observe_rtt_ms 都经 extra 传入。 - 浮点统一 round(...,3)；之后 _t_obs=None、清桶；追加进 chunks 并返回同一 dict（chunks[] 只落 result.json / results.jsonl，不写 events.jsonl）。 - PP 特例：PP 的 decision_wall_ms 不是墙钟差而是「fresh 步往返 + 桶」，故 close 增可选参数 decision_wall_ms: float | None = None——给出时直接采用且不要求先 start（接口签名里的唯一扩展，S3 按此调用；〇′ 共享接口同步补一句）。 - absorb_orphan(ms: float, n: int) -> None：把外部回收的未归属语言耗时（如 Astra 的 abort_chunk）累加进内部 _orphan_ms / _orphan_n，局末与桶一起输出；ms 非有限或为负、n 为负 → ValueError。取代一切临时属性写法。 - orphan() -> dict：返回 {"orphan_lang_ms": _bucket_ms + _orphan_ms, "n": _bucket_n + _orphan_n} 后清桶并清零 absorb 累计；全空返回 {"orphan_lang_ms": 0.0, "n": 0}。不动 _t_obs（局末悬空的 start 由 attach 记 dangling_start=True）。

summarize_chunks(chunks, fields=CHUNK_FIELDS) -> dict - 每个字段先按 chunk 的 phase 归段，再剔除该字段为 None 的条目（顺序：标 phase → 缺失过滤 → Astra 分层；分层子集不得重新按位置切前三条，例如某层第一条若 phase=steady 就只进稳态），输出 {field: {"n", "first", "second", "third", "steady_mean", "steady_p50", "steady_p95"}}；n=0 时整段为 {"n": 0}；second/third 不存在时 None。 - first/second/third 取对应 phase 的值（该 phase 的条目被过滤或不在本层时为 None）；steady = phase 为 steady 的值；局内 chunks 不足 4 条（无 steady phase）时 steady 统计退回该层全部值并标顶层 steady_short=True（顶层只看 decision_wall_ms）。顶层另给 n_decisions = len(chunks)。 - 字段名一律 _ms 语义、值为毫秒；不再沿用 framesamp 的 _s 秒制。 - lang_summary：对 lang_calls 按 kind 分组（含 ask），每组同样三段统计（字段 ms），外加 {"total_ms_counted": Σ LANG_KINDS, "n_ask": k}。

attach_policy_timing(timing, timer, *, gpu_name, model_kind) -> dict - model_kind not in MODEL_KINDS → ValueError。原地写并返回 timing：chunks、chunk_summary、lang_calls、lang_summary、gpu_name（原样接收，可 None；助手不探测 GPU，口径 e）、orphan_lang_ms（调 timer.orphan() 的值，n 写 orphan_n）、dangling_start（bool）、conservation。 - 对 Astra，chunk_summary 额外加 by_planner_review = {"planner+review", "planner_only", "review_only", "neither", "no_lang"}：前四格按 has_planner × has_review（has_review = 该 chunk 的 lang 明细含 kind review，由 S4 经 extra 写入）划分且要求 lang_ms > 0，no_lang 收 lang_ms == 0 的 chunk（continue_last 后直接 client.infer）；每层各一份三段统计，空层写 {"n": 0}；无任何 chunk 带 has_planner 键时不写。 - conservation = {"kind": model_kind, "expected": len(chunks), "checked": 实际完成比较的条数, "violations": int, "missing_fields": int, "overhead_pct_p50": float | None}（smvla 另加 lang_split_available: bool）；三种 kind 统一：action_rtt_ms is None 的 chunk 跳过比较、不算违例、不计入 checked，计入 missing_fields（除此之外 serial / pp 的 missing_fields 为 0，smvla 另按下文计数），逐 chunk： - serial（FrameSamp / GroundSG / Astra）：base = action_rtt_ms + lang_ms；违例 ⇔ decision_wall_ms < base - 1.0（1 ms 计时噪声）；overhead_pct = (decision_wall_ms - base) / decision_wall_ms；overhead_pct_p50 只报数，不判 FAIL；超过 20%（SERIAL_TOL）交用户裁决。 - pp：违例 ⇔ |decision_wall_ms - (action_rtt_ms + lang_ms)| > 1.0；overhead_pct_p50 同式（应≈0）。 - smvla：两类不等式，任一不成立计 1 次违例：①decision_wall_ms ≥ observe_rtt_ms + action_rtt_ms − 1.0；②lang_ms ≤ server_infer_ms + 1.0 且 server_infer_ms ≤ action_rtt_ms + 1.0。overhead_pct = slack_ms / decision_wall_ms（slack_ms 只报数不判）。missing_fields 只检 observe_rtt_ms、server_infer_ms，缺任一的 chunk 计 1 违例并计数（不当作通过）。 - 分母为 0 的 chunk 跳过百分比、仍做违例判定；全空 → expected=0, checked=0, violations=0, missing_fields=0, overhead_pct_p50=None。 - smvla 语言拆分：lang_split_available = True 当且仅当每个 chunk 都有至少一条 kind lang_in_forward 的 lang 明细（服务端回复带 lang_ms）；否则为 False，该局 LANG_SPLIT 不出 PASS（客户端判定行写 LANG_SPLIT=FAIL reason=unavailable）。 - PASS 条件（WALL_DECOMP 与 SPEED_TABLE 共用）：violations == 0 且 missing_fields == 0 且 checked == expected；缺必要字段不得视为通过。 - 幂等：首次调用把写入的全部键（含 orphan_lang_ms、orphan_n、conservation）深拷贝成快照存在 timer._attached；第二次及以后调用不再读 orphan()、不再重算，直接把同一快照的深拷贝写回 timing 并返回，结果与第一次逐键相等。

判定行格式：各模型守恒验收统一最小键集 WALL_DECOMP=PASS model=<m> kind=<serial|pp|smvla> chunks=<n> violations=0 overhead_pct_p50=<x|na>，各模型可在其后追加键（如 missing_fields=0 checked=<n> expected=<n>）；值取自 timing["conservation"]；PASS 按上文 PASS 条件，否则写 FAIL。

异常一览：未 start 就 close → RuntimeError；非法 kind / 负数或 NaN ms / extra 撞保留键 / 非法 model_kind → ValueError；重复 start → 覆盖不报；close 前无 add_lang → lang_ms=0.0, n_lang=0；局末有未归属 lang → 进 orphan_lang_ms，不并入任何 chunk。

PonderPounce 逐文件改动

口径：

  • 每步往返 R_k 记进 step_rtt_ms[]，step_rtt_ms[] 的长度等于 actions_received；
  • 第 k 步的 S2 耗时记 s_k（该步没触发 S2 时为 0），由服务端测、经审计块带回；
  • 桶 B = 自上一个 fresh 步以来非 fresh 步（含首个 chunk 之前的 hold 步）的 Σ s_k；
  • 在 fresh 步 f 上生成一条 chunk 记录：
  • decision_wall_ms = R_f + B
  • lang_ms = B + s_f
  • action_rtt_ms = R_f − s_f
  • server_infer_ms = s1_infer_ms_f
  • 守恒式代数核对：action_rtt_ms + lang_ms = (R_f − s_f) + (B + s_f) = R_f + B = decision_wall_ms，恒等成立。共享助手对三个值各自 round(...,3)，舍入后残差最多约 1.5e-3，所以测试阈值取 ≤ 3e-3 ms。共享助手守恒式的 PP_TOL_MS=1.0 是口径上限，测试用的 3e-3 ms 更严。

盲区与待实测

  • s2_infer_ms 与 s1_infer_ms 的计时含 torch.cuda.synchronize()。父类 S1 输出已经 [0] 落到 CPU（注释写 CPU float32），隐式同步过，sync 基本无增量；S2 的 cognition 留在 GPU 上，加 sync 会把原本异步的尾巴计进 S2，可能让真机的步时略增。要在真机上做一次 sync 开/关对照（第 16 条），确认对 action_rtt_ms 的影响 < 1%。
  • action_rtt_ms = R_f − s_f 里还含 _fire_s1、_dispense、序列化和网络。服务端没有单独报 _dispense 和编解码耗时，所以「网络与编解码」只能用 R − s1 − s 的残差估计，不是直接测量。
  • 重连时服务端可能已经处理过断线前那次观测（ep.tick 已 +1、可能已触发 S1/S2），重发后会二次触发，桶和 n_s1_fires 会多算。这种情况记进 reconnect_steps，报表剔除；真实频率待实测。
  • chunk_fresh 依赖第三方私有字段 Chunk.cursor 和 _dispense 内的自增顺序，靠 gitlink 锁死加断言测试。H=1 且 s1 周期大于步长时，cursor 判据会误判，由客户端 n_s1_fires 递增断言兜底；真机配置是 H>1，没有实测过 H=1。
  • 审计开时多出的 pp_timing 字段约 150 B/步，对 RTT 的影响未测，可以拿 OBS_EQ 的审计关跑次做 RTT 基线对照。
  • gpu 字段取服务端进程 cuda:0；CUDA_VISIBLE_DEVICES 重映射后它反映的是真实型号，A40 和 Ada 按这个字段分组，不按客户端分组。

八 附带发现：FrameSamp 客户端 add_buffer 等待存在死循环风险（单独一节，独立子任务 S6）

现象：写 FrameSamp 方案时子代理读到 src/robomme_ood_eval/models/framesamp_modul.py::run_loop 的 if not epstate.action_plan: 分支里：

resp = client.add_buffer(pack_buffer(...))
while not resp.get("add_buffer_finished", False):
    time.sleep(0.1)

循环体内从不重新取 resp。服务端首包只要不带 add_buffer_finished=True，评估进程就永远空转，日志里不会出现任何错误行，属 AGENTS.md 第 23 条的「静默空转作业」，Monitor 过滤器也抓不到。

现状为什么没炸：第三方 third_party/mme-vla/src/mme_vla_suite/serving/websocket_policy_server.py 的 add_buffer 分支同步处理后直接回 {"add_buffer_finished": True, "add_buffer_time_ms": …}，首包恒带该标志，所以循环体从未执行过。风险在于：服务端异常回字符串（_roundtrip 会先抛 RuntimeError，这条路径安全）之外，任何回了 dict 但缺该键的情况（例如将来换服务端实现、或 _roundtrip 的 _last_audit 弹出逻辑改动）都会触发。
