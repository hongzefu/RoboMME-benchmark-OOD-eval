翻译范围 = 进 main 的全部文本文件，约 75 个：src/ 22 个、evaluate.py、进 main 的测试与辅助约 45 个、pyproject 与 .gitignore 注释、README、public-gate.yml。翻什么：注释、docstring、命令行帮助、日志、报错与异常文案、测试断言里引用的原文、测试数据文件里的中文值。不翻什么：代码逻辑、标识符、判定行（NAME=PASS k=v 形式本来就是 ASCII，键名与取值一律不动）、数据集名 hard-verify／ood（来自 benchmark 包）。判定标准不是「看起来英文了」，而是扫描整份白名单，一个 CJK 字符都没有。行为不变的证据：同一组测试在 dev 上翻译前后通过数一致。

四、ckpt 不再有默认：改什么、机制是什么

现状。src/robomme_hard_eval/servers/__init__.py 里有一张 DEFAULT_CKPTS 表，三个模型（FrameSamp+Modulation、GroundSG、SimpleMemVLA）写死了本机与 NFS 的绝对路径；models/framesamp_modul.py、models/smvla.py、models/pp.py 三处写法是「命令行没给 --ckpt 就用表里的」。全仓只有这 4 个文件引用 DEFAULT_CKPTS，测试与 dev-scripts 里都没有（已用 git grep -l DEFAULT_CKPTS 核实）。

改后机制。evaluate.py 不知道、不猜、不下载任何权重；权重在哪完全由使用者每次用 --ckpt <目录> 指定。改动两处：

  1. 入口拦截：解析完参数后，若模型需要权重而没给 --ckpt，立刻 parser.error（退出码 2）。哪些模型需要权重，由每个模型类的 requires_ckpt 属性声明（dummy 与 astra 为 False），入口不手写名单。
  2. 模型层删默认：三处「没给就用表」改成调用 require_ckpt(cfg, model)，没给就抛同一句错；表整段删除。这是给绕过入口、直接 import 包的人准备的第二道保险。

后面的链路不变：路径传给模型类 → 预检目录里有没有 params/、assets/、history_config.txt → 起服务端并把路径写进服务元数据 → 评估结束把路径与逐文件 sha256 写进 log.json。

同步脚本步骤（sync_to_main.sh）

  1. 前置：当前分支 dev；clean 判定为空；HEAD == origin/dev。
  2. 闸门：check_public_lang.py、check_public_paths.py、check_manifest.py 全 PASS。
  3. 短测：uv run --no-sync python -m pytest $(清单内测试文件) -q。
  4. 取 main：git worktree add --detach <scratch>/main-sync origin/main；git -C <wt> log -1 --format=%B 必须含 Dev-Source:，否则停。
  5. 复制与暂存：git archive HEAD -- $(cat manifest) | tar -x -C <wt>（取的是已提交字节）；待删 = git -C <wt> ls-files 减去清单，喂给 git -C <wt> rm -q --pathspec-from-file=-；新增与修改喂给 git -C <wt> add --pathspec-from-file=manifest；5 个 gitlink 用 update-index --cacheinfo 160000,<sha>,<path> 对齐 dev。
  6. 无差异：git -C <wt> diff --cached --quiet 为真 → 打印 SYNC_MAIN=NOOP，跳到第 8 步。
  7. 提交与推送：commit「Sync from dev @<短 sha>: <dev 最新 subject 的英文摘要，由你给或我拟>」+ 尾行 Dev-Source: <完整 sha>；git -C <wt> push origin HEAD:main（快进，被拒即停）。
  8. 收尾：git worktree remove <wt>；打印 SYNC_MAIN=PASS dev=<sha> main=<sha> files=<n> changed=<m>。--dry-run 执行到第 6 步止。

五、runbook（阶段顺序，命令形状）

  1. S1：git branch dev main；git push -u origin dev；git checkout dev；记 OLD_MAIN=$(git rev-parse origin/main) 进留档。
  2. S2-0：git mv src/robomme_hard_eval src/robomme_ood_eval；逐文件替换；改 pyproject.toml；uv lock；uv sync；RENAME_CLEAN；全量短测；commit「1.22 包改名 robomme_ood_eval」；push dev；记 BASE1。
  3. S2 第一波：同一条消息派 A1、T0、D（opus、isolation: "worktree"、sub/S2-A1: 等前缀）；主会话同时写 dev-scripts/release/ 与 Action 等。按 A1 → T0 → D 合并：每个先第一次审查（核越界、worktree 复跑验收、sonnet 审查）→ git merge --no-ff <TIP sha> → 第二次审查（全量短测、文件清单核对）→ push。三块合完后主会话提交自己的工具，push。
  4. S2 第二波：派 A2；同样两次审查后合并、push。
  5. S2 第三波：同一条消息派 T1～T4；按 T1 → T4 合并；主会话写 README、生成清单、首跑五条判定行；commit、push。
  6. S3：逐项过前置清单 → git tag private-main-20261009 <OLD_MAIN>；git push origin private-main-20261009 → git worktree add --detach <scratch>/orphan，其中 git checkout --orphan main-new、git rm -rq .、按清单 git archive dev -- $(cat manifest) | tar -x、逐路径 add、对齐 5 个 gitlink、commit「Initial public release」+ Dev-Source: → git push --force-with-lease=main:<OLD_MAIN> origin main-new:main → git fetch；git branch -f main origin/main；git branch -u origin/main main；删临时 worktree；本机工作副本仍在 dev。
  7. S4：scratchpad 下 git clone --branch main --recurse-submodules；UV_LINK_MODE=copy uv sync；dummy 1 任务 × 1 档 × 1 局（2 次 reset，在 P3 阈值内）；pytest；CJK grep。
  8. S5：dev 改一行英文注释、commit、push；sync_to_main.sh 得 changed=1；再跑一次得 NOOP；看 main 上 public-gate。
  9. S6：gh api -X PUT repos/hongzefu/RoboMME-benchmark-OOD-eval/branches/main/protection（禁强推、禁删除、不要求 PR），dev 同样；重跑 PUBLIC_SECRETS、SUBMODULE_PUBLIC；问你一次后 gh repo edit --visibility public --accept-visibility-change-consequences。
