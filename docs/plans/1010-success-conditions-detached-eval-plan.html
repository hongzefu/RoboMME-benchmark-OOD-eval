# 在 is_obj_stopped_onto 中，只赋值一次

五、代理能退出：交给普通监督程序

一句话：代理把完整任务交给后台程序，确认它已经接手后退出；普通程序按固定规则继续运行。这里有两个职责：调度程序负责“下一步跑什么”，监督程序负责“程序还在正常工作吗”。

可以做到。已有 continue_full_eval.py 的 Controller.tick/report/replace_expired 能持续调度四席、核报告、仅在明确 TIMEOUT 后补交 48 小时作业；seat.py 已有领取、心跳与共享预算，run_eval_gl.sh 已有无进展看门狗。缺口是控制器自身异常后无人接管、停止和最终复制仍需主会话，以及没有已建立的聊天推送。

环节拟新增保证与交接条件
一次提交新 launch_detached_eval.sh 读取钉死代码、身份清单、预算和作业白名单的运行合同；取全局运行锁，只创建自己的确定命名会话，重复启动接手或明确拒绝。配置／载体指纹不符即拒绝。
接续复用现有控制器，不写第二套调度队列。为 state.json 增加心跳、终态、明确错误类型和停止请求；控制器失败独立于席位活着与否。确定性校验失败不自动重启。
监督器自身本机 shell 守护监督 Python 子进程；异常退出最多重启 2 次，间隔 30 秒。控制器意外死亡最多自动恢复 2 次，先核提交／启动意图和运行锁；身份重试仍由原账本约束，不重新领取已接受回合。
停止本机 STOP_REQUEST.json → 可见共享停止文件 → 控制器不派新工作 → 精确停止清单内工作会话／数字 step → 保存中断现场。占位作业保留；未知资源归属不操作。SIGKILL／失联不伪造成功退出码。
48 小时到期仅 sacct 明确 TIMEOUT 后机械申请对应一席；最多四席并存，不提前申请，不把查询失败当到期。新合同必须写最大接替轮数及总运行截止时间；未批准的值为 0／禁启动，不能无限续费。
最终收尾阶段报告通过后按 accepted 白名单复制完整三类产物，逐文件字节数与 SHA256 校验，再写全量报告。复制冲突保留两端并报错，原始错误尝试和停止现场保留；本方案不自动删除 NFS 源、不取消占位作业。
交接后交付原子输出本机 status.json/status.html、阶段报告、最终 result.md、alert.json；无变化只更新机器心跳。代理退出前核实成功、异常和监督器故障三条链路，不以 tmux 活着替代交接。
通知边界：文件状态与失败报告可以由普通程序生成；它们不等于用户已收到主动通知。当前工具列表没有通用 automation_update，本轮不建立聊天推送或代理自动唤醒。若未来提供受支持的通知接口，可增设只在阶段完成、失败或需人工处理时触发的一次短回合；不让通知回合调度工作、不反复报告无变化。本方案基础执行链不依赖该能力。

三、运行合同与退出状态

拟 detached-eval/1 合同放在 artifacts/<新运行名>/contract.json，配置来源文件和默认值钉在启动提交，launch.md 逐项记录覆盖。必填：两个仓 SHA、carrier／配置指纹、每阶段身份清单 SHA、models／seeds／任务档位范围、原 accepted 复用映射、全部预算、精确作业 ID、每席资源／端口、最长报告等待、无进展阈值、自动接替次数上限、总截止时间、保留占位作业及通知模式。

终态：RUNNING → COMPLETED | STOPPED | NEEDS_ATTENTION
成功：所有阶段完整性通过 → COPY_VERIFIED → COMPLETED
错误：契约／预算／提交状态不明 → NEEDS_ATTENTION，不自行改判据
停止：STOP_REQUEST → 不派新局 → 精确收工作 step → STOPPED
进程故障：无未决提交／启动意图且合同有效 → 最多 2 次恢复
监督器退出：shell 守护最多 2 次恢复；耗尽写 alert.json
未知 SIGKILL／主机失联：心跳过期，不能当成正常完成。

每个状态必须带时间、运行名、版本、事件编号、错误类别、最后进展、受影响席位、输出路径和退出状态。控制器每 15 秒原子心跳；监督器每 30 秒检查，连续 180 秒未更新进入故障核证；报告超时采用合同值，不能用心跳替代真实任务进展。提交／启动意图不明只报错，不以进程消失推断“没提交成功”。

首次启动通过 flock 保证运行唯一 owner；外层和控制器各保留独立锁。一次采集原始进程 PID 与启动时间，禁止用裸 pgrep -f。模型服务器健康检查与首次推理分别验收，沿用每局预算和原无进展看门狗，不加入高频 nvidia-smi。
